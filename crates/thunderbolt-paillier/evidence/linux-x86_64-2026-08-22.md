- Debian Linux 6.1.180-1, x86_64.
- Intel Xeon 2.60 GHz; 96 logical CPUs, two sockets, two NUMA nodes.
- Rust 1.90.0 (`1159e78c4`), Cargo 1.90.0, LLVM 20.1.8.
- Assembly builds were pinned to CPUs 0-3, used at most four Cargo jobs, ran at
  niceness 10, had a 900-second timeout, and had a 16 GiB address-space limit.
- Timing tests were pinned to CPU 4, single-threaded, niceness 10, with the same
  timeout and memory limit.
- The shared host load average before the run was 13.16 / 23.27 / 31.53. CPU 4
  was pinned but not exclusively isolated, so scheduler and sibling-core noise
  remain material uncertainty.

Observed peak resident memory was 463,080 KiB for O0 assembly, 416,208 KiB for
O3 assembly, 446,116 KiB for default tests, 400,840 KiB for decrypt timing, and
34,088 KiB for proof-response timing. No command exceeded two CPUs on average;
the timing measurements used 99% of one CPU.

## Statistical experiments

Both release experiments used 2,048 measured samples, 64 warmup samples,
balanced shuffled class order, fixed public inputs, and one pinned CPU.

| Operation | Class means (ns) | Welch t | Approx. df | Harness label |
|---|---:|---:|---:|---|
| Decrypt | 58,599,437.976 / 58,649,941.076 | -1.105318 | 1319.26 | `no_large_signal_observed` |
| Proof response | 15,510,556.848 / 15,513,613.597 | -1.572872 | 1828.42 | `no_large_signal_observed` |

The harness uses `|t| >= 10` only as an investigation heuristic. These results
did not cross that heuristic, but they do not establish the absence of timing
leakage. The decrypt command took 2:54.90 including release build/setup; the
proof-response command took 35.50 seconds with the release artifacts cached.
The recorded statistics are finite. The current harness adds explicit
non-finite/zero-standard-error rejection, variance reporting, deterministic
Welch unit tests, and optional per-sample CSV retention without changing the
timed operation boundaries. The historical run did not retain per-sample CSV.
